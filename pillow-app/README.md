# 不离不弃 · 陪伴留言与管理后台

这是现有“我可能需要一个枕头”页面的完整应用版本。原 GitHub Pages 体验页继续保留；本目录的后端还没有在线部署。真实姓名、联系方式、留言、口令和测试数据库都不能提交到 GitHub。

## 已按用户回复确定的规则

- 几位指定同学分别登录，普通管理员可以查看全部留言、分配负责人和跟进。
- 超级管理员创建、停用和重新开通管理员账号；仅超级管理员可以删除留言。
- 不要求会友注册，昵称可不填；希望被联系时留微信号或手机号。不希望被联系时，不保存联系方式。
- 跟进进度：待回应、已联系、陪伴中、已结束；内部备注记录处理过程。
- 24小时内人工回应。当前按“从后台复制联系方式，再人工联系”实现；不发自动邮件、短信或微信，不会自动提醒轮值同学。
- 不自动删除留言。删除留言同时删除相关内部备注。审计日志只记录记录编号、操作者、动作及时间，不保留被删内容。托管方备份有独立的保留周期，不能声称即时清除所有备份。
- 暂无公开留言墙、AI回复、自动危机识别、付款或强制注册。

## 本地查看

需要 Node.js 22或以上及 pnpm。

```powershell
pnpm install --frozen-lockfile
pnpm check
pnpm test
pnpm dev
```

首页：`http://127.0.0.1:4178/`；工作台：`http://127.0.0.1:4178/admin/`。

本地使用 PGlite（嵌入式 Postgres），数据库与随机初始化密钥均放在被 Git 忽略的 `.local/`。开发服务器只监听本机。第一次开通的本地测试链接见 `.local/setup-url.txt`，该链接不要发给真实管理同学。默认本地测试邮箱为 `owner@example.test`；这不是已确认的正式负责人邮箱。自行设置密码，无固定默认密码。重启后本地测试数据保留。

## 正式部署到 Netlify

源码继续托管在 GitHub。GitHub Pages不能运行后端；Netlify托管完整应用及 Postgres。按照 Netlify 官方 Database 自动配置流程：<https://docs.netlify.com/build/data-and-storage/netlify-database/getting-started/>。

1. 重新连接 Codex 中的 Netlify（当前连接返回认证失效）。连接到本仓库，Base directory 设为 `pillow-app`。读取本目录的 `netlify.toml`，publish 为 `public`，functions 为 `netlify/functions`。
2. 在 Netlify 环境变量中设置（仅 Functions 需要，不能进入公开 HTML）：
   - `SUPERADMIN_EMAIL`：待用户提供的正式负责人邮箱。
   - `BOOTSTRAP_SECRET`：独立生成至少32字符的随机初始化密钥。
   - `RATE_LIMIT_SECRET`：另一个至少32字符的独立随机密钥，用来隐藏限流标识。
   - `APP_ORIGIN`：正式站点的完整 origin（例如 `https://example.netlify.app`，不含末尾斜线）。
   - `PUBLIC_SUBMISSIONS_ENABLED=false`：初次部署保持关闭。
3. 部署时自动创建 Netlify Database，应用 `netlify/database/migrations/` 迁移。只给服务端数据库访问权限。`.netlify` 已加入 `.gitignore`，链接后产生的本机站点状态不提交。
4. 负责人通过 `https://正式域名/admin/#setup=初始化密钥` 自己设置密码。密钥在URL片段中，页面读取后立即移除；不要在公开群或 GitHub 中发送链接。初始化邮箱由服务端环境固定，不接受浏览器任意指定；已有超级管理员后不能再次初始化。完成后移除 `BOOTSTRAP_SECRET` 并重新部署。
5. 在同学账号页创建账号，复制一次性开通链接，人工发给本人。链接有效期24小时，一次使用；重置开通链接会立即撤销原密码和全部登录会话。此流程不发送邮件。
6. 在部署站点使用明确标记的虚构测试内容，检查登录、开通、权限、提交、刷新后读取、联系与分配、并发冲突、删除以及手机页面。确认指定同学能实际值守后，再把 `PUBLIC_SUBMISSIONS_ENABLED` 改为 `true` 并重新部署。
7. 正式链接验证成功后，再把旧 `/pillow/` 入口更新为正式链接或跳转，避免会友继续填写体验版。

没有完成这些步骤前，不要把“代码已完成”写成“真实留言已开放”。当前没有创建收费资源或正式管理员。

## 安全和运行边界

- 服务端校验全部权限；浏览器是否显示删除按钮不决定授权。账号停用后，下次请求立即被拒绝；重置、修改密码和退出会清除数据库中的相应会话。
- 密码使用带独立盐的 scrypt，数据库只存哈希。会话使用256位随机口令，数据库只存哈希；生产 cookie 为 Secure、HttpOnly、SameSite=Strict，8小时到期。没有公开注册接口。
- 写请求核验同源 Origin，API不开放跨域；参数化 SQL；页面采用外部脚本与 CSP，用户内容用 textContent 显示。前端不使用 localStorage 保存留言或会话。
- 表单内容和请求体限制、隐藏机器人字段、每IP每小时5次留言、登录IP和邮箱限流。限流是边界保护，不保证阻挡分布式恶意流量。上线后根据实际流量再判断是否需要验证码。
- 重试用随机 requestId 去重；多人跟进用 revision 防止覆盖；联系人和私密留言不出现在匿名API响应或日志中。
- 删除与备注写入使用事务；删除日志不存原文。没有自动清理留言的任务。
- 超级管理员忘记密码需由维护者走受控恢复流程；普通管理员由超级管理员重新发开通链接。本版不提供邮箱找回。
- 申请删除的匿名留言者需通过群负责人处理，不能仅凭短编号公开查询或直接删除留言。
- 后端使用Netlify Database正式SDK，但线上数据库迁移、云函数、域名cookie和移动端浏览器仍需部署后验收。本机自动测试使用同一Postgres SQL迁移与应用处理器，不能代替云端验收。
